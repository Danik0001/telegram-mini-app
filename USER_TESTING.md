# План проверки на пользователях

**Статус: не проведено.** Технические проверки не заменяют исследование. Для проверки дизайна привлечь минимум 5 артистов/битмейкеров, включая новичков и пользователей Telegram на iOS/Android.

Сессия 25–35 минут. Получить согласие на заметки/запись. Попросить проговаривать мысли, не подсказывать названия кнопок. Для настоящего звука нужен рабочий MVP; в дизайн-прототипе оценивать обнаружение функций, понимание шагов и ограничений.

| Задание | Наблюдение | Критерий для следующей итерации |
|---|---|---|
| Найти инструментал и перейти к записи | Путь, ошибки навигации | Не менее 4/5 без подсказки |
| Записать MID, добавить BACK, перейти к FX | Понимание обязательной дорожки | 4/5 завершают путь |
| Изменить только BACK и включить BYPASS | Понимание независимых настроек | Нет ошибочного ожидания сброса FX |
| Завершить микс и закрыть студию | Понимание WAV и потери сессии | Все объясняют необходимость скачивания |
| Создать 3 Samples, добавить в избранное | Параметры, квота, библиотека | 4/5 находят результат |
| Объяснить Wallet и перейти к Community | TON/ASIQ, внешний переход | Нет ожидания кредитного магазина/соцленты |

Фиксировать: participant ID, устройство, задание, успех без помощи/с помощью/провал, время, затруднение, точную цитату при согласии, severity и предлагаемое исправление. После каждого задания — SEQ 1–7. В конце — что было непонятно и оценка общей простоты.

Приоритет: P0 — потеря результата/непонятное финансовое действие; P1 — блок ключевого пути; P2 — замедление; P3 — косметика. Исправить P0/P1, повторно проверить изменённые пути. Цели выше — критерии будущей проверки, а не достигнутые результаты. Конверсию и вовлечённость подтвердить только после внедрения аналитикой.
